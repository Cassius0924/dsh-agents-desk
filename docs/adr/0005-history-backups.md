# ADR-0005 变更历史：扫 `.bak-*` + 轻索引，不建版本库

- 状态：已决（2026-10-22）

## 背景

规则文件直接决定 agent 行为，改错一次可能连「怎么改回来」都不会了。候选方案：git（项目内的文件天然有版本，但 `~/.dsh` 不在 git 里）、插件自建版本库（全文快照）、复用每次保存的 `.bak-<时间戳>`。

本机已有前者模式：`~/.dsh/profiles/web/cordis.patch.yml.bak-20261017-101242` 这类备份是日常操作产物。

## 决策

1. 每次保存（含回滚、生成写入）都在目标同目录写 `<file>.bak-<YYYYMMDD-HHmmss>`（`COPYFILE_EXCL` 防碰撞）。
2. 历史视图 = 扫描目标目录的 `.bak-*` + 插件索引 `$DSH_HOME/agents-desk/history.json`（记录 path、时间、字节、digest、操作来源：手动/生成/回滚）。索引丢失可全量重建，不作为唯一真相。
3. 支持：列表、与当前内容 diff、与另一备份 diff、一键回滚。
4. **回滚本身也是一次保存**：先把当前内容备份，再写目标（带版本令牌），因此回滚可撤销。
5. 不做保留策略（文件都很小，全留）；列表按时间倒序，默认显示最近 20 条。

## 后果

- 好处：零新存储引擎；和用户已有的 `.bak` 习惯一致；索引只是加速，坏了不影响恢复。
- 代价：备份散落在各目录，跨作用域没有统一时间线（v1 只在单文件视图里看历史）；文件名冲突在同一秒内两次保存时依赖 `COPYFILE_EXCL` 加序号。

## 备选方案

- **SQLite/内容寻址版本库**：能力强，但对「几个 Markdown 文件」是过度设计。拒绝（用户也选了前者）。
- **依赖 git**：`~/.dsh` 常不在版本控制里，且项目 AGENTS.md 可能未提交。只能作为补充，不能作为唯一历史。
