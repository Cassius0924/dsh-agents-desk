# ADR-0003 生成规则：v1 设置页按钮（host 侧一次模型调用），已有文件出改进提案

- 状态：已决（2026-10-22）
- 相关：ADR-0001；先例：Codex `/init`、Claude Code `/init`

## 背景

Codex 与 Claude Code 的 `/init` 都是**行为约定**：分析仓库 → 生成草稿 → 已存在则提改进而非覆盖 → 写前可审。Claude 的交互版还会用子 agent 探索、追问缺口、给出可审提案。

DSH 里实现有两条路：

- **host 侧生成**：插件自己扫仓库事实，调一次 `ctx.llm`，拿到 Markdown；不依赖当前会话，不需要额外 key，输出可控。
- **agent 侧生成**：`/init` 命令让当前 agent 用工具探索再写；更懂代码，但要把「命令 → 提示 → 写盘」串起来，且吃会话上下文。

## 决策

v1 做 host 侧生成，行为对齐 Codex/Claude：

1. 入口：设置页 → 选中作用域（默认项目根）→「生成草稿」。
2. 事实采集由插件做，只喂确定性事实：`package.json` scripts/deps、锁文件类型、`go.mod`/`Makefile`/`pyproject.toml`/`Cargo.toml`、顶层目录、README 标题、现有 `AGENTS.md` 与全局 `AGENTS.md`。
3. 一次模型调用（可选模型，默认 `agentDefaultModel`），输出上限固定；提示词要求「只写事实里存在的命令，缺失就省略」。
4. 目标文件已存在 → 不直接覆盖，生成**改进提案**：服务端算行级 diff，返回 hunks；前端逐块「接受/拒绝」，接受后合并成新内容再走一次正常保存（带版本令牌与备份）。
5. 目标不存在 → 显示完整草稿，确认后写入。
6. 所有生成物都必须经过预览；没有「后台自动写」。

v1.1 再加 `/init`：先验证 DSH 命令能否把提示注入当前会话（`CommandResult` 只有 success/error，需要另找 seam）；做不到就只保留按钮，不硬造。

## 后果

- 好处：零额外凭据；事实与模型分离，能明确告诉用户「这条命令来自 package.json」；生成是确定性输入，可复现。
- 代价：不如 agent 探索深入（不会读源码细节）；需要维护事实采集器；diff 逐块接受是 UI 工作量最大的一块。
- 预算：一次调用，输入 ≤ 8k 字符事实，输出 ≤ 4k token；失败不写盘。

## 备选方案

- **纯 LLM 自由生成**：会编造命令。拒绝。
- **只做 `/init`**：依赖宿主命令→提示的管线，且每次生成都占会话上下文。降级为 v1.1。
- **直接覆盖已有文件**：违背先例与用户预期。拒绝。
