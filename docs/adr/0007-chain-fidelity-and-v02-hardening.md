# ADR-0007 v0.2：生效链按宿主真实渲染复算，写入与读取路径收紧

- 状态：已决（2026-10-22）
- 相关：ADR-0002（写入路径）、ADR-0004（生效链）、ADR-0005（历史备份）

## 背景

v1 的生效链把「文件字节数」当预算：按顺序累加，预算不够时截断当前文件。宿主实际行为不同：

- 渲染预算统计的是**整条提示文本**（`<system-reminder>` 框架、intro、每节 `Instructions from: <path>` 标题、omit/truncate 标记），不是文件字节和；
- 超预算时先按**从宽到窄**丢弃整个文件，只保留最具体的后缀；后缀仍放不下时，只对**最后一个**文件做 UTF-8 安全截断；
- 去重是 trimmed 内容的 SHA-1，空文件也会参与去重；同一目录四种候选同组，两个全局根同组；
- 全局显示路径按宿主规则：默认根写作 `~/.dsh`、`~/.agents`，被环境变量改写的根写作 `$DSH_HOME`、`$DSH_AGENTS_HOME`。

v1 同时把读取型历史路由当成了可信输入：`/history` 与 `/history/diff` 只校验备份名，没有校验目标路径是否在白名单内；写入用 `copyFile` 直接操作未校验路径。这些在 v0.2 一并收紧。

## 决策

1. **复算宿主渲染，不估算**：`buildChain` 按宿主 `render.ts` 的同一顺序重建文本（intro、section 标题、marker、system-reminder 框架、UTF-8 截断与 compact intro 兜底），`budget.used` 等于整段渲染文本的字节数。已用宿主 `renderAgentInstructions` 在多组预算下逐字节比对（1148、774、500、300、200 B 全部一致）。
2. **预算/候选名/项目根标记以默认值为准，并显式声明假设**：返回值新增 `assumptions`（maxBytes 65536、maxSourceBytes 1 MiB、`.git`、四个候选名），由 UI 明示「静态复算，预设改写后实际注入可能不同」。不在 v0.2 猜测当前会话的预设配置。
3. **发现走目录列举**：一次 `fs.listDir` 取一目录的全部候选与子目录，读文件并发 8；不再对每个候选各做一次 resolve+stat。子目录动态候选仍只做三层、2000 目录上限的启发式枚举，并标注「工具触碰后注入」。
4. **读取路由白名单化**：`/history`、`/history/diff` 必须带 `cwd`，目标路径先过 `isAllowedPath`，备份必须是同目录 `<basename>.bak-*` 普通文件。
5. **写入路径双校验**：`lstat` 拒绝符号链接；`fs.processPath` 得到真实宿主路径后再过白名单（含 realpath 根回退），防止项目内链接把写入带出白名单。
6. **备份语义改为「写成功后再落备份」**：写入前用 `fs.readText` 读旧文本作为备份内容，`fs.writeText` 成功后再以 `wx` 写 `.bak`。这样备份内容与本次覆盖的内容严格对应，也不会出现「备份成功但写入失败」的孤儿文件；代价是极端崩溃窗口内可能缺一份备份，此时返回 `backupError`。
7. **错误码稳定化**：所有失败统一 `{error, code, status}`，客户端按 code 本地化；历史索引的 `source`（save/rollback）回填到列表。

## 后果

- 好处：UI 的「预算占用 / 为什么被省略 / 为什么被截断」与宿主真实注入一致；跨站或误用请求无法借历史读接口读任意 `.bak` 文件；客户端不再依赖中文错误文案。
- 代价：复算逻辑与宿主版本绑定（0.2.1-rc.2），升级宿主需回归；预设改写预算时视图会标注不确定性而不是自动读取；备份从「写前复制」改为「写后落盘」。
- 不做：当前会话实况 digest 对比、预设级预算读取（仍属 v1.1）。
