# ADR-0001 职责边界：只编辑宿主真正会加载的指令文件，不做第二套注入

- 状态：已决（2026-10-22）
- 相关：`docs/research/2026-10-22-agents-md-plugin-landscape.md`

## 背景

DSH 的指令加载器只认固定文件：每个用户全局根一个 `AGENTS.md`，项目层每目录四个候选名（`AGENTS.md` / `CLAUDE.md` / `*.local.md`）。生态里已有插件走另一条路：`kingzhz/dsh-global-rules` 把 `$DSH_HOME/rules/*.md` 作为 system-prompt 段落注入（order 100），从而得到多文件、独立开关、独立排序。

两条路的代价不同：多文件注入灵活，但它绕过官方指令链的预算、去重与权威层级——同一段规则到底谁赢，模型和用户都说不清。

## 决策

本插件只做「DSH 真实加载的指令文件」的编辑与解释：

- 作用域：`$DSH_HOME/AGENTS.md`、`$DSH_AGENTS_HOME/AGENTS.md`、项目根到 cwd 的各目录候选、`.local` 覆盖层、子目录 `AGENTS.md`。
- **不做**片段库、编译区、`rules/` 多文件、system-prompt 注入。
- 需要「多文件管理」时，用项目层天然的候选机制（同目录 `AGENTS.md` + `.local`），或用户自己的目录结构；插件只负责让这些文件可见、可改、可解释。

## 后果

- 好处：模型看到的和插件展示的完全一致；预算/去重/优先级全部由宿主一套逻辑决定；升级宿主时只有一条契约要适配。
- 代价：没有「一条规则一个文件、单独开关」的体验；用户要复用规则只能复制粘贴（或后续另做片段功能，见 ADR-0003 的边界）。
- 明确放弃：与 `kingzhz` 的功能对等——只对等「能管理规则」的结果，不对等其注入机制。

## 备选方案

- **system-prompt 注入**：功能最强，但改变权威层级、与官方预算互不知情，且让「指令链」出现第二个真实来源。拒绝。
- **片段 + 编译区**：单一真实来源，但用户明确表示不做多文件，v1 不引入。
