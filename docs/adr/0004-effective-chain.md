# ADR-0004 生效链：静态计算 + 会话实况，且绝不假装「已生效」

- 状态：已决（2026-10-22）
- 相关：ADR-0001

## 背景

用户改完规则最常问的两个问题是「为什么没生效」和「模型到底看到了什么」。宿主不提供「当前生效指令」的查询接口，但两侧信息都可拿到：

- **静态**：按加载器同一套规则（两个全局根 → `.git` 项目根 → 祖先链 → 每目录四候选 → 内容去重 → 1 MiB 忽略 → 64 KiB 渲染预算）可以精确复算。
- **实况**：会话事件里有 `agent-instructions` 消息（含 baseline 标记与每个 scope 的 `set/replace/remove`），可读出本次会话实际注入的版本。

## 决策

1. 生效链默认**静态计算**：不选会话也能看；每个文件显示字节、token 粗估（标注方法与误差）、状态（加载/去重/超 1 MiB 忽略/预算裁剪）、来源。
2. 选中会话时叠加**实况**（best effort）：从该会话事件读出已注入的 scope 与 digest，和磁盘 digest 对比，标记「已同步 / 磁盘更新 / 本会话从未加载」。
3. **生效承诺如实**：只根据宿主实际行为说三种话——「下一条消息会带上」「需要新会话」「当前会话已是最新」。宿主版本差异导致不确定时，显示「不确定（宿主未提供确认）」而不是猜。
4. 不实现「立即刷新」按钮；不做伪造的工具触碰。若后续实测证明某种触碰可靠，再加，并且仍以实况为准。

## 后果

- 好处：这是现有插件都没做全的差异化能力；把「规则没生效」从玄学变成可核对的状态。
- 代价：静态复算必须跟宿主规则逐条对齐，宿主换代时要维护；会话实况依赖事件格式（v4 JSONL），只能 best effort、失败时降级为静态视图。
- 待实测：改全局/项目文件后，既有会话在**下一条消息**是否真的收到增量更新（源码暗示会，需一次真实会话验证后再定文案）。

## 备选方案

- **只显示文件内容**（现有插件的做法）：不解决「为什么没生效」。拒绝。
- **自己注入一次以强制刷新**：可能改变会话权威内容，且 gxx 的实现已证明依赖活跃 agent 与沙箱放行。拒绝。
